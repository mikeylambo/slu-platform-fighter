# SLU Fighter Animation & Character Pipeline v0.01

## Goal

Make roster growth a repeatable content-manufacturing process rather than repeated engine work.

A fighter pack is the source of truth:

```text
fighters/<fighter-id>/
├── fighter.json       # authoritative gameplay/content definition
├── render.json        # 3D presentation/rig/animation mapping
├── asset-audit.json   # generated by Blender audit, not hand-authored
└── assets/
    └── model.glb
```

Normal fighter creation must not require editing simulation or registry source code.

## Lifecycle

- `draft`: incomplete pack; missing animation roles and placeholder assets allowed.
- `playable`: all semantic roles must exist, but adapted and author-required animation may remain.
- `certified`: no author-required roles; mechanics, rig, sockets, palettes, assets, and replay determinism have passed certification.
- `release`: animation contract may contain only dedicated, retargeted, or procedural roles. Adapted placeholders are not release-quality.

Lifecycle is deliberately distinct from flagship release scope.

## 3D asset strategy

Gameplay exists on an authoritative 2D simulation plane. Presentation is 3D.

The standard path is:

```text
greybox capsule / test rig
        ↓
audited rigged placeholder asset
        ↓
SLU humanoid rig compatibility
        ↓
retargeted movement library
        ↓
fighter-specific dedicated animation
        ↓
asset audit
        ↓
Fighter Forge annotation / hitbox authoring
        ↓
certification
```

The runtime retains GLB/3D assets. We do not rasterize 3D fighters into sprite atlases.

## Animation contract

`content/animation-contract.json` defines the semantic roles the engine understands. Render packs map each role to an asset clip and quality grade.

Grades:

- `dedicated`: authored specifically for this fighter/action.
- `retargeted`: intended action transferred from a compatible rig and accepted as production-quality.
- `adapted`: usable real clip, but not final-quality for this role.
- `procedural`: generated at runtime by a defined presentation system.
- `author_required`: intentionally incomplete.

A role name describes semantic intent, not an engine animation-state name. This keeps content portable across the web lab and later production-engine ports.

## Semantic materials

Every standard fighter exposes these presentation channels:

`primary`, `secondary`, `accent`, `skin`, `hair`, `metal`, `energy`

`render.json` maps those semantic channels to actual material names in the model. Fighter palettes operate on semantic channels instead of hardcoded material slots.

## Sockets

Weapon/effect/entity attachment points are semantic names mapped to bones, for example:

- `hand_r`
- `hand_l`
- `head`
- `root`

Fighter-specific sockets may be added without changing the kernel.

## Asset audit

Run:

```sh
blender --background --python scripts/blender/audit_fighter.py -- fighters/<id>/render.json
```

The audit checks:

- model file exists and imports;
- expected armature exists;
- semantic material bindings resolve;
- socket bone bindings resolve;
- mapped animation clips exist;
- animation roles are known;
- a machine-readable `asset-audit.json` is produced.

`asset-audit.json` is evidence, not source-of-truth content.

## Pack commands

```sh
npm run fighter:new -- my-fighter
npm run fighter:check
npm run fighter:build
npm run content:doctor
```

`fighter:new` creates a draft with the full current animation contract preclassified as `author_required`.

`fighter:check` validates all fighter and render packs and reports animation grade counts/missing roles.

`fighter:build` validates and generates the active fighter registry. Draft fighters are excluded from active runtime content.

## Provenance

Every external source used by a fighter must record at minimum:

- role;
- asset name;
- author;
- source URL;
- license identifier;
- license URL when available;
- SHA-256 when the exact source artifact is stored or distributed.

Do not promote a fighter to `certified` with unresolved asset provenance.

## Reference implementation lineage

The pack/generator/validator/provenance model was implemented after reviewing the MIT-licensed Super Bash Folds project. SLU's schemas, lifecycle, 3D runtime strategy, animation contract, deterministic gameplay definitions, and Blender certification path are expanded for this project rather than inheriting its combat simulation or sprite-atlas runtime.
